# 智研 · 演示视频脚本（6 分 45 秒）

> 项目：智研 · AI 考研备考助手｜全国高校 AI Web 开发挑战赛（B 组 / 山东建筑大学）
> 用途：参赛演示视频（MP4 / ≥1080p / 普通话讲解 / 建议配字幕）
> 设计原则：**只演示真实存在的功能**。当前前端共 5 个页面（首页 / 院校专业库 / 认知科普 / 学情诊断 / 错题本）；Agent 编排与 MCP 为后端能力，通过接口演示，不虚构页面。

---

## 一、录制前准备

### 1. 环境检查（录制前一天做完）

| 项 | 检查内容 |
|---|---|
| 后端 | `http://localhost:8080/api/health` 返回 `status: ok`（数据库连通） |
| 前端 | `http://localhost:5173` 能正常打开，右上角不显示"后端未连接" |
| 模型额度 | 智谱免费档有限流，**录制前先手动跑一遍 AI 评分**，确认能出分 |
| 演示数据 | 提前准备一个学生 ID（如 `demo-video`），先做一次测评，让错题本有内容 |
| 浏览器 | 用无痕窗口（避免书签栏、插件图标入镜），缩放 100%，窗口 1920×1080 |
| 桌面 | 关闭微信/QQ 弹窗通知，隐藏任务栏无关图标 |

### 2. ⚠️ 绝对不能入镜的内容

- **API Key**：IDEA 运行配置里的 `ZHIPU_API_KEY`、`.env` 文件、Swagger 的 Authorize 弹窗
- **数据库密码**：MySQL 客户端连接窗口、`application.yml` 明文
- **个人隐私**：其他项目窗口、聊天记录、桌面文件名

> 演示 Agent 接口时，用 Swagger UI 或终端 `curl`，**不要打开 IDEA 的 Run Configuration**。

### 3. 录制参数

| 项 | 建议值 |
|---|---|
| 分辨率 | 1920×1080（必须 ≥1080p） |
| 帧率 | 30fps |
| 语速 | 每分钟 220–240 字（本稿按此配速，正常聊天语速即可） |
| 工具 | OBS Studio（免费）或 Windows 自带 `Win+G` |
| 收音 | 有线耳麦或手机录音后期对齐；避免键盘声 |
| 字幕 | 建议用剪映/必剪自动识别后校对，或用文末 SRT |

## 二、分镜脚本

### 第 1 段｜00:00–00:35　开场：说清"解决什么问题"

**画面**：首页（`/`），鼠标不急着点，停在标题区。

**台词**：

> 考研备考最难受的，往往不是不努力，而是不知道劲儿该往哪使。
> 不知道流程和时间节点，不知道自己到底哪一章薄弱，计划做了一堆却执行不下去。
> 我们做的这个项目叫"智研"，一个 AI 驱动的考研备考助手，想解决的就是三件事：该不该考、考什么、怎么考。
> 下面我用六分钟，把这套东西完整走一遍。

---

### 第 2 段｜00:35–01:15　院校专业库：数据是查出来的，不是模型编的

**画面**：点进"院校专业库" → 选城市"济南"、勾选"985" → 点"查询" → 点某院校"查看专业"。

**台词**：

> 先看院校专业库。目前收录了山东地区为主的 28 所院校、104 个热门专业，字段是结构化的：层次、是不是 985/211、自划线、考试科目、学制。
> 这里有一个刻意的取舍——**我们不做分数线**。因为分数线每年都在变，让模型去"回忆"一个数字，几乎必然产生幻觉。所以查询只给稳定的事实，分数请以研招网公告为准。
> 你看，筛选是直接查数据库，结果可复现，跟模型无关。

---

### 第 3 段｜01:15–02:15　认知科普：RAG 让每个回答都有出处

**画面**：点进"认知科普" → 左侧点一个主题（如"学硕与专硕的区别"）→ 右侧 AI 答疑框输入"数二和英二分别是什么"→ 等回答出现，鼠标停在下方的来源上。

**台词**：

> 第二个页面是认知科普。左边是我们整理好的固定讲解，覆盖术语、学硕专硕、时间线这些高频困惑。
> 右边这个答疑窗口，不是让大模型自由发挥。
> 我们先把考研常识整理成结构化语料，用**本地嵌入模型**把它变成向量库——这一步完全跑在自己电脑上，不要任何 API Key，也没有调用费用。
> 你提问的时候，系统先从向量库里检索出最相关的几条事实，再交给大模型组织语言。
> 所以重点看这里：**每条回答下面都带着来源**。模型只负责把事实说人话，没有机会凭空编造。

---

### 第 4 段｜02:15–03:50　学情诊断：从"感觉不行"到"具体哪章不行"

**画面**：
① 输入匿名 ID，选"数学"，抽题数量 5，点"开始测评"；
② 快速答两道选择、跳过填空，到一道大题，在输入框写两三行，**再演示一次拍照上传**（切到"含特殊符号可拍照"）；
③ 点"提交并诊断"，等结果，停在结果页；
④ 展开一道**主观题**的"逐题解析"，指一下"AI 评分 / 评语 / 参考答案"；
⑤ 再点"查看我的诊断"，展示掌握度与薄弱知识点。

**台词**：

> 这一页是整个项目的核心。
> 输入一个匿名 ID，选科目和抽题数量，就能开始测评。题目按知识点分层抽，不是随机糊一堆。
> 作答方式有两种：直接打字，或者——像这种数学填空题，根号、分数不好打——**拍照或截图上传**，后端用视觉模型识别图里的答案再判分，这是多模态能力的落地。
> 提交之后分两条判分线：选择题、填空题这类客观题，由 Java 判分引擎精确比对；而解答大题、英语作文、翻译、政治简答这类主观题，答案不唯一，交给大模型评分——它返回一个分数、是否达标，还有一段评语。
> 这里有个关键设计：**一旦模型限流或者返回格式不对，这道题就标记为"待复核"**，不计分、不进错题本、不影响掌握度。宁可暂时不判，也不让脏数据污染你的学习记录。
> 最后的诊断报告不是一句"你基础薄弱"，而是落到知识点：每个点的掌握度用 BKT 算法算出来，哪几个点拖后腿，一目了然。

---

### 第 5 段｜03:50–04:25　错题本：错了不再错

**画面**：点进"错题本" → 切到"数学" → 展示列表 → 点"随机重做"或"导入错题"。

**台词**：

> 诊断里答错的题会自动进错题本，也可以把平时做错的题手动导进来。
> 支持按科目筛选、随机重做。答对一次就标记为攻克，不用自己拿本子抄。
> 这一块看着简单，但它是"诊断—练习—反馈"闭环里最容易被忽略的一环。

---

### 第 6 段｜04:25–05:20　Agent 编排与 MCP：AI 不只是聊天框

**画面**：打开 `http://localhost:8080/swagger-ui.html` → 展开 `POST /api/agent/run` → 请求体填 `{"goal":"我想考山东大学的计算机，该怎么准备","studentId":"demo-video"}` → 执行 → 展示返回里的 `steps` 数组（每步 name / status / durationMs）。

**台词**：

> 除了页面上的功能，后端还有一层 Agent 编排。
> 用户输入一句话，比如"我想考山东大学的计算机，该怎么准备"。系统先做意图识别——**这一步不走模型，用数据和关键词匹配**，稳定、零延迟、零费用——然后决定要调哪几个工具：查院校、查科普、查学情诊断，按顺序执行，最后汇总成一段建议。
> 每一步的名称、状态、耗时、产出，都以结构化数据返回。所以"AI 是怎么得出结论的"是可追溯的，不是黑盒。
> 这部分目前通过接口提供，没有做独立页面——这是我们主动精简的结果。
> 同时，我们把能力按 MCP 协议暴露成了 5 个标准工具：院校查询、院校详情、专业查询、考研知识问答、学情诊断。任何支持 MCP 的 AI 客户端，不改我们一行代码，就能直接调用。

---

### 第 7 段｜05:20–06:10　技术架构与 AI 安全：为什么这么做

**画面**：切到技术文档 PDF 的架构页（或一张架构图 / 代码截图），缓慢滚动。

**台词**：

> 技术上，后端是 Spring Boot 3.5 加 Spring AI 1.1.8，模型用智谱的 GLM-4.7-Flash，前端是 Vue 3 加 Element Plus。
> 整条链路有一条贯穿始终的原则：**事实和算法放在代码里，模型只负责组织语言**。
> 掌握度用 BKT 算、判分用规则加模型分级、院校数据是结构化的。这样结果可复现、可测试，也不会因为模型换个版本就飘。
> AI 这块我们做了七层：大模型集成、本地 RAG、Agent 编排、多模态识别、MCP 工具暴露、主观题评分，以及安全可控。
> 安全不止是说一说：接口做了 CORS 白名单、数据库用只授权单库的低权限账号、日志走统一框架不打印 SQL、模型失败一律降级为待复核。
> 代码里有 66 个自动化测试，覆盖判分、诊断、编排和 HTTP 入口，全部通过。

---

### 第 8 段｜06:10–06:45　价值与收尾

**画面**：回到首页，镜头慢慢拉远；或切到本人出镜（可选）。

**台词**：

> 对考生来说，它把"信息差"和"计划焦虑"，变成了一张能执行的清单：知道自己差在哪、下一步练什么。
> 对学校来说，这套"结构化数据 + 可解释算法 + 大模型组织语言"的架构，可以复用到其他备考和助学场景。
> 代码、技术文档、测试报告都在仓库里，欢迎评审老师指正。谢谢。

## 五、录制与剪辑提示

### 1. 画面节奏

- 每段开头先停 0.5 秒再动鼠标，给剪辑留切口；
- 鼠标移动放慢，点击前稍作停顿；
- 输入文字时不要逐个字母慢慢敲，提前粘贴好再一次性提交。

### 2. AI 限流的应对（重要）

免费档模型有并发限制。如果演示 AI 评分时遇到限流：

- **不要剪掉**。可以说："这里正好遇到限流，你可以看到它被标记为待复核，而不是随便给个分——这就是我们的降级设计。"
- 这反而是加分项，说明系统在真实网络波动下是安全的。

### 3. 时间控制

| 段落 | 目标时长 | 累计 |
|---|---|---|
| 开场 | 35s | 0:35 |
| 院校库 | 40s | 1:15 |
| 认知科普 | 60s | 2:15 |
| 学情诊断 | 95s | 3:50 |
| 错题本 | 35s | 4:25 |
| Agent + MCP | 55s | 5:20 |
| 架构与安全 | 50s | 6:10 |
| 收尾 | 35s | 6:45 |

若超时，优先压缩**院校库**和**错题本**（各砍 10 秒），核心的学情诊断不要动。

### 4. 导出

- 格式 MP4（H.264），分辨率 1920×1080，码率 8–12 Mbps；
- 文件名建议 `智研-演示视频-B组-山东建筑大学.mp4`；
- 字幕可选择硬字幕（烧进画面）或外挂 SRT，赛题两者都接受。
