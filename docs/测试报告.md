## 二、问题修复记录（按严重程度）

### P0 致命（本轮修复 3 个）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| P0-1 | **最小化窗口后页面「自动重新打开」**（用户报告两次未修好） | Vite dev 客户端：窗口最小化期间 WebSocket 断线（休眠/锁屏/网络瞬断），还原窗口时执行 `location.reload()` 整页刷新（`vite/dist/client/client.mjs:962-970` 源码级确认）；叠加项目在 Desktop（OneDrive 同步目录）下文件 mtime 变动触发 full-reload | 三重修复：① **生产模式成为推荐路径**——前端构建产物已进后端 `static/`，8080 一个端口跑完整应用，无 HMR 链路，现象根除；② vite.config.js 显式声明 watch 忽略范围（node_modules/.git/dist/target），降低 OneDrive 误触发；③ 启动指南同步「测试/演示用生产模式，改代码才用 dev」 |
| P0-2 | **错题本越权**：不传 `studentId` 即可删除/判分任意学生的错题 | 归属校验被 `studentId != null` 前置条件保护——不传就跳过校验（fail-open） | 服务层 `requireStudentId()` fail-closed（null/空白一律拒绝）；Controller 参数改必填；删除改条件删除（`WHERE id=? AND student_id=?`） |
| P0-3 | SPA 路由回退 500（生产模式子路由全挂） | 转发控制器映射了 "/" 且 path 变量未排除点号 → `forward:/index.html` 被自己再拦 → StackOverflowError | 只保留 `/{path:[^\\.]*}` 单 pattern（不含点号、不映射 "/"），踩坑记录写进注释 |

### P1 高（本轮修复 8 个）

| # | 问题 | 修复 |
|---|---|---|
| P1-1 | App.vue 上一轮「修复」的副作用：窗口还原 → probe 失败 → **503 警告框自动弹出**（用户感知的「弹窗自动打开」之一） | 探活重构：自动探活失败**静默**（只更新圆点），仅首次加载允许弹提示；加 in-flight 去重；轮询改为有限 36 次（约 3 分钟，覆盖后端启动全程）+ 成功后停止；`onScopeDispose` 清理监听器与定时器 |
| P1-2 | ScienceChat 发送期间点「清空」→ 按索引取气泡得 undefined → TypeError → 全局错误弹窗（「弹窗自动打开」之二） | 持有气泡对象引用 + `stale` 过期标记：清空时给在途消息打标，返回时静默丢弃；失败文案不再进入下一轮 history |
| P1-3 | 错题本幂等的「清空重做结果」是**空操作** | MyBatis-Plus `updateById` 跳过 null 字段（`FieldStrategy.NOT_NULL`），`setLastRedoCorrect(null)` 不生成 SET 子句 → 改用 `LambdaUpdateWrapper.set(column, null)` 显式置空；**并修正了单测**（原来只验证传给 mock 的实体对象，验证不了 SQL——典型的「Mock 测了不该测的」） |
| P1-4 | 错题本并发双提交重复入库 | schema 加唯一键 `uk_student_qcode_src(student_id, question_code, source)` + insert catch `DuplicateKeyException` 回退更新路径 |
| P1-5 | OCR 识别失败（限流/模糊）被当成**学生答错**：冤判、拉低 BKT、污染错题本 | `ocr.error() != null` 时该题标记 invalid：不计分、不进错题本、不更新 BKT，反馈明示「图片识别失败」；总分母剔除 invalid 题 |
| P1-6 | submit 无事务、无逐题隔离：中途失败留半套脏数据（BKT/历史/错题本） | `@Transactional(rollbackFor)` + 循环内 BKT/历史写入逐题 try-catch（单题失败不中断整轮） |
| P1-7 | 图片上传无大小/MIME 限制，base64 无上限 → 内存放大与 DoS 面 | base64 ≤ 8MB（约 6MB 原图）、非法 base64 拒绝、answers ≤ 50 条、空 answers 拒绝（原来 NPE 500） |
| P1-8 | 全局异常缺失：业务异常变 500、缺参数变 500、错误无去重（弹窗轰炸） | 新增 `GlobalExceptionHandler`：IllegalArgumentException→400（中文消息）、MissingServletRequestParameter→400、DuplicateKey→409、其他→500（通用文案不泄露细节）；main.js errorHandler 相同错误 3 秒去重 + 懒加载 chunk 失败提示 |

## 五、测试环境与方法论备注

1. **测试数据隔离**：所有联调使用独立测试学号（bb-test 等），结束后全部清理，不影响真实用户数据。
2. **Mock 边界**：单测一律不连 DB/模型/网络（毫秒级、可重复）；集成与黑盒测试打真实环境，两层互补。
3. **已知遗留（记录在案，非本轮范围）**：SimpleVectorStore.load 原子写、DJL tokenizer 并发压测、MCP 鉴权、schema 版本迁移——均已在代码注释或本文档标注风险与建议路径。
4. **复现方式**：`cd aiweb && mvn test`（单测+覆盖率）；黑盒脚本按第四节场景用 curl 复演；E2E 按启动指南第五节路线走一遍。
